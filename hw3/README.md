## Сборка

```bash
g++ -std=c++17 -O2 -Wall -Wextra -Wpedantic -Iinclude src/*.cpp -o funny_analyzer
```

## Запуск

Файл:

```bash
./funny_analyzer examples/hw3_typed.funny
```

Строка:

```bash
./funny_analyzer --string 'function f(x: int) returns y: int { y = x + 1; }'
```

`--compact` выводит JSON в одну строку

```bash
./funny_analyzer examples/hw3_typed.funny --compact
```
При успешном запуске из файла или через `--string` тот же JSON сохраняется в `output/annotated_ast.json`. Файл создаётся автоматически и перезаписывается при каждом успешном запуске, в том числе при семантических ошибках, чтобы можно было исследовать частично аннотированное дерево.

Коды возврата: `0` — ошибок нет; `1` — лексические, синтаксические или семантические ошибки; `2` — ошибка CLI/I/O.
Диагностики содержат фазу(lexer | parser | semantic), строку, столбец, смещение от начала исходного текста и описание.

## Интеграция с hw2 и выбранное подмножество типов

Поддерживается грамматика HW2: объявления `function` и формул `name(...) => predicate`, параметры, несколько возвращаемых переменных, `requires`, `ensures`, `uses`, блоки, присваивания, кортежные присваивания вызовов функций, `if/else`, `while/invariant`, `assert`, `assume`, арифметические выражения, сравнения, логические связки, вызовы функций/формул и кванторы.

В задании требуется унификация простых типов (`int`/`bool`/`string`/`func`) **или выбранного подмножества**. В этой реализации выбран поднабор, соответствующий грамматике HW2:

- `int` — целые значения;
- `int[]` — массивы целых значений;
- `bool` — внутренний тип результата предикатов, условий, формул и контрактов; грамматика не допускает объявления переменных типа `bool`;
- тип результата вызова функции определяется её сигнатурой; несколько результатов представляются в аннотации как `tuple<int, ...>`.

Имена функций обрабатываются через таблицы сигнатур `(типы параметров -> типы результатов)`, а не как значения типа `func`.

`length(array)` принимает ровно один аргумент типа `int[]` и возвращает `int`.
Арифметические операторы и `<`, `<=`, `>`, `>=` требуют операнды `int`; `==` и `!=` проверяют совместимость типов операндов.
Строковые литералы, `bool`-переменные, вложенные массивы (`int[][]`), пользовательские приведения и объявление двух функций с одинаковым именем не поддерживаются.

## Имена, области видимости и вызовы

Сначала собираются сигнатуры всех функций и формул, поэтому вызов ранее или позже определённой глобальной функции разрешён. Повторные глобальные объявления и повторные имена в области функции диагностируются с позицией первого объявления.
Область функции включает параметры, возвращаемые переменные и все переменные из `uses`; квантор создаёт вложенную область с переменной-связывателем.
Неизвестные имена, несовместимые типы, неправильное количество аргументов и несогласованные кортежные присваивания приводят к диагностике.

## Вывод типов локальных переменных (задание на +2 балла)

Для переменной `uses x` без аннотации тип выводится из первого корректного присваивания. Например, `x = 10` выводит `int`, `x = someArray` при `someArray: int[]` выводит `int[]`, а `x[i] = value` - `int[]` для `x`. Выведенный тип записывается в таблицу символов и в `uses[].type` аннотированного AST.
Ошибочное выражение не используется как основание для вывода типа; чтение невыведенной переменной и несовместимые последующие присваивания диагностируются.

Тесты — `tests/semantic/positive/inference_from_index.funny`; `tests/semantic/positive/inference_and_contracts.funny`.

## Формат аннотированного AST

Схема исходного AST сохранена, а у узлов выражений и предикатов добавляется поле `type`. Типы выражений включают `int`, `int[]`, `error` и `tuple<...>` для вызовов с несколькими результатами; предикаты имеют тип `bool`. При обнаружении семантических ошибок анализатор старается продолжить проверку оставшихся узлов.

Пример:

```json
{
  "kind": "BinaryExpr",
  "type": "int",
  "pos": { "offset": 40, "line": 2, "column": 7 },
  "op": "+",
  "left": { "kind": "Variable", "type": "int", "name": "x" },
  "right": { "kind": "IntLiteral", "type": "int", "value": 1 }
}
```

## Ограничения

- Проверка типов выполняется после построения AST
- Ошибочные подвыражения получают тип `error`
- Локальные объявления доступны только в форме `uses`
